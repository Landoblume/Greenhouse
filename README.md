# Greenhouse

A plant journal for a two-person household, on both iPhones. Each plant has its
own record (Latin name, nickname, photos). Records can be **stapled** together
when you combine pots, or **split** when you take cuttings, and the history
keeps the whole family tree. Care reminders, anniversaries and USDA-zone advice
are shared between both phones through iCloud.

## Build and run

Needs Xcode 26 and [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).
The `.xcodeproj` is generated and not committed.

```sh
./install.sh --launch     # build a debug build and put it on the plugged-in iPhone
scripts/testflight.sh     # archive a release build and upload it to TestFlight
```

Tests (logic only; they use an in-memory store and never touch iCloud):

```sh
xcodegen generate
xcodebuild test -project Greenhouse.xcodeproj -scheme Greenhouse \
  -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO
```

## One-time setup for TestFlight

1. **App Store Connect app record.** Go to [appstoreconnect.apple.com](https://appstoreconnect.apple.com),
   then Apps → **+** → New App. Choose iOS, a name (App Store names are unique,
   so "Greenhouse" may be taken; the home-screen name stays "Greenhouse"
   regardless), bundle ID `com.landenblume.greenhouse`, any SKU.
2. **CloudKit schema.** TestFlight builds use CloudKit's *Production*
   environment, which only knows the record types deployed to it.
   1. Open a debug build (`./install.sh --launch`) on a phone that's signed in
      to iCloud. It uploads the schema to *Development* by itself.
   2. Check Settings → Developer → "CloudKit schema" says **Ready**.
   3. In the [CloudKit Console](https://icloud.developer.apple.com/dashboard),
      open `iCloud.com.landenblume.greenhouse` → Schema → **Deploy Schema Changes…** → Deploy.

   Do this again whenever the data model (`Model/GreenhouseModel.swift`) changes.
3. **Testers.** In App Store Connect: Greenhouse → TestFlight → Internal Testing → **+**,
   make a group, and add testers. A tester has to be a user on your App Store
   Connect team first (Users and Access → **+**, any role). Internal testers
   skip Apple's beta review, so builds show up as soon as they finish processing.

## Testing sharing

Debug builds sync to CloudKit *Development* and TestFlight builds to
*Production*. These are separate databases, so **both phones must run the same
kind of build** to see each other's plants. Before installing from TestFlight,
delete any debug build from the phone, so its local copy of the Development data
doesn't follow it over.

1. Phone A: Start a household → Settings → **Invite to household** → send the link (Messages works).
2. Phone B: open Greenhouse → **I was invited** → tap the link in Messages.
3. Add a plant on either phone. It appears on the other within about a minute while both apps are open.

## Notes

- **Species data** (`Resources/species.json`, generated by `scripts/build_species.py`).
  About 300 houseplants and popular cultivars come from `scripts/houseplants.json`,
  with each zone range read off a cited extension or botanical-garden page (mostly NC
  State and Missouri Botanical Garden). The herb and garden rows in the script itself
  were drafted from general references and aren't checked yet. Care cards link the
  source, or say the range is unchecked. Fix a row and rerun the script.
- **ZIP → zone** uses [phzmapi.org](https://phzmapi.org), a free mirror of the USDA map data.
  If it's down, pick the zone by hand in Settings.
- **Photos** are shrunk to at most 2048 px before saving, because they count against
  the household owner's iCloud storage.
